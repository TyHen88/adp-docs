Process 3

FRD wizard — a sentence becomes a scope

Three steps, and they are the inside of one wizard, not three siblings of the workbench. That is why the left menu does not list them — they live inside FRD 작업하기, they were not removed.

STEP 1
요구사항 직접 입력
Write what should change, in business language, and pick what it applies to. Selecting a screen is optional.
STEP 2
AI 인터뷰
Not one-shot analysis: the AI investigates, asks one question at a time, and only then fixes a result.
STEP 3
개발 범위 확인
The confirmed analysis shown as work scope. Still no worktree.

The interview loop

01
The AI investigates the requirement and the planning repo
ScreenPickWorker · read-only · working directory = the clone
It reads the index and the screen documents; it changes nothing.
↓
02
Is there a judgement it cannot ground in evidence?
new screen or existing? · API, batch, permission or data too? · operation or new development? · which system? · error, permission and retention conditions
Five questions at most, one at a time. The planner can stop early with 현재 내용으로 범위 정리.
↓
03
If yes: one question as structured JSON, and the run ends
question + investigation summary saved → state WAITING_ANSWER
Nothing is held while a human thinks: no process, no credential file, no account lock.
↓
04
The answer starts the next run, which resumes the session
--resume · FrdRunSpace · continuation sends only a short instruction
Measured: 220 of 350 seconds per run were exploration, and every one-line answer used to pay it again.
↓
05
No questions left → the analysis result is written
screens · backend changes · completion criteria · items to confirm → state PICKED
Questions, answers and the final result are saved as one state transition.
One Claude run per turn, not one long-lived conversation

A bidirectional process held open would die with the browser, the server restart, or the lunch break. Turn-based runs survive all three — and a session that the reader rejected is deliberately not remembered, so a bad turn does not poison the next one.

Eight states

StateLabelWhat the planner does
ANALYZING요구사항 분석 중Wait. Closing the browser does not stop it
WAITING_ANSWER답변 필요Answer, or finish with what is there

SCOPE_REVIEW개발 범위 확인Press FRD 작업하기 — or the backend-only fast track

Pasted text is never inlined into the instruction

source_text has no length limit, so “short enough to fit” was never true: inlining can exceed the Windows argv limit of about 32 KB, and imperative sentences inside pasted text land somewhere they can be read as instructions. The text is written to a run-only file and the instruction carries only its path.

Two beans, on purpose

ScreenPickService is the database half; ScreenPickWorker submits to the executor. Merging them makes the call a self-invocation, the Spring proxy is skipped, and @Async never fires at all — the “background” work runs on the request thread. The same split appears in the development-result apply path.

Two ways out of scope review

FRD 작업하기 — the normal path

The first write, so this is where the branch and worktree are cut from the clone's HEAD and the state moves to DRAFTING. The full creation contract is on Git & worktrees.

개발요청서 바로 만들기 — backend only

Offered only when no screen is selected and no question is open. It skips the workbench and the worktree, but the requirement and the AI's evidence still travel into the development request. Since 2026-09-02 this means backend-only, and nothing else: a simple screen change is an SRT.

Not every FRD row is planner work

Every SRT quietly creates a bridge FRD with source_kind = SRT, born at SCOPE_REVIEW and never shown in the UI. A query that counts FRDs without filtering source_kind counts those too.
