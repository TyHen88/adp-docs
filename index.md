# ADP Builder — Reference Documentation

> A complete reference map of `we-adk-builder`: what it is, how it is built, and what every feature does. Written for engineers and analysts who need to understand the whole system without reading 714 Java files.

`we-adk-builder` (internally: **ADP Builder**) is a **single-server, browser-accessed web application** that lets a planner (기획자) turn a business requirement into a **development request package** that a development organisation can act on — with Claude Code doing the analysis, screen drafting and document generation along the way.

**One work unit is one FRD.**

```text
FRD 1 = one work item = one git worktree = one person
```

## The 20-second version

| Question | Answer |
|---|---|
| What does it do? | Turns a planner's requirement into a development request package, using Claude Code for analysis and screen drafting. |
| Who uses it? | Planners (기획자), plus a super administrator who registers projects and users. |
| Where does the content live? | A **planning repository** on GitLab, owned by the planning team. Builder keeps a clone and per-FRD worktrees. |
| What does Builder never do? | Read the production source system. Extraction is a separate tool (`we-adk-builder-extractor`) a human runs. |
| How does AI run? | The server executes the `claude` CLI as a subprocess, with **the signed-in user's own credentials**, in an isolated config directory. |
| What is the deliverable? | A **development request (DR)** — a package, not a single document — delivered as a ZIP plus a GitLab issue. |
| What comes back? | Updated as-is screen material, unit-test results, and integration-test scenarios — which feed the green-zone artifacts. |

## About these documents

- **Source of truth is the Markdown.** Every `NN-name.html` in this folder is generated from `NN-name.md` by `tools/build_html.py`. Do not hand-edit the HTML.
- Rebuild after editing any Markdown file:

```bash
python docs/adp/tools/build_html.py            # rebuild all
python docs/adp/tools/build_html.py --check    # exit 1 if any HTML is stale
```

- Adding a page: create `NN-name.md`, add one line to `NAV` in `tools/build_html.py`, add a card here, rebuild.
- These pages **describe** the system; they are not the product's decision record. Where a decision is contested, the canonical documents are `CLAUDE.md`, `docs/artifacts.md`, `docs/data-model.md`, and `docs/superpowers/specs/*.md` — each page links to the relevant one.
- Korean is kept for anything that appears in the code, the UI, or the domain (`FRD 작업하기`, `개발요청서`, `그린존`). English explains it. A name that appears on screen is never translated silently — see the [glossary](23-glossary.html).
